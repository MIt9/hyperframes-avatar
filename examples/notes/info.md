Для **Hyperframes** такий компонент лягає в архітектуру просто ідеально, бо вся його логіка є **суто детермінованою від поточного часу кадру (**`currentTime` **/** `frame`**)**.

Замість того щоб рендерити важке відео з прозорим фоном (WebM), компонент `<SpriteAvatar/>` може збирати персонажа на льоту з легких PNG-шарів або одного спрайт-шита, споживаючи мінімум пам'яті та рендерячись миттєво.

## 1. Архітектура JSON-схеми / Props компонента

Щоб компонент був універсальним і легко конфігурувався (зокрема й автоматично через LLM-агента, який генерує сценарій), його конфігурацію варто розділити на **Manifest персонажа** (асети) та **Timeline-тригери**:

```typescript
export interface AvatarPackManifest {
  id: string;
  gridSize: [number, number]; // напр., [96, 96] у оригінальних пікселях
  layers: {
    base: string; // Голова + торс без рота, очей і рук
    eyes: {
      open: string;
      blink: string;
      surprised?: string;
    };
    mouth: {
      closed: string; // RMS < 0.05
      half: string;   // 0.05 <= RMS < 0.25
      open: string;   // RMS >= 0.25
      smile?: string;
    };
    poses: Record<string, string>; // 'point_viewer' | 'point_up' | 'shrug' | 'idle' | 'listen' | 'fist'
  };
}

export interface SpriteAvatarProps {
  pack: AvatarPackManifest;
  position?: 'bottom-right' | 'bottom-left' | { x: number; y: number };
  scale?: number; // Масштабування (напр. 4x -> 384x384px)
  
  // Дані для автоматичного Lip-sync (pre-computed RMS масив, напр. 30 або 60 значень на секунду)
  audioEnvelope?: number[]; 
  audioFps?: number;

  // Таймлайн жестів (може генеруватися LLM на основі транскрипту)
  poseKeyframes: Array<{
    time: number; // в секундах (напр. 1.2)
    pose: string; // 'point_up'
    emotion?: 'open' | 'surprised';
    bounce?: boolean; // Чи робити мікро-стрибок при зміні пози
  }>;

  // Стилізація "Стікера"
  stickerStyle?: {
    outlineWidth: number; // напр., 8px
    outlineColor: string; // '#FFFFFF'
    shadowBlur: number;   // 20px
    shadowOpacity: number;
  };
}

```

## 2. Детермінований рушій станів (State Resolver)

Усередині рендер-циклу Hyperframes для кожного кадру в часі t компонент обчислює 4 параметри без жодного внутрішнього `useState` (щоб підтримувати паралельний рендеринг кадрів):

1. **Поза рук (**`activePose`**):** Шукаємо останній елемент у `poseKeyframes`, де `keyframe.time <= currentTime`.
2. **Пружинний імпульс (**`bounceOffset`**):** Якщо від моменту зміни пози минуло менше `0.18s` (наприклад, \\Delta t = t - \\text{keyframe.time}), застосовуємо коротку затухаючу криву:

   $$\\text{scaleY} = 1 + 0.06 \\cdot \\sin\\left(\\frac{\\Delta t}{0.18} \\cdot \\pi\\right), \\quad \\text{translateY} = -12 \\cdot \\sin\\left(\\frac{\\Delta t}{0.18} \\cdot \\pi\\right)$$

   Це дає той самий «живий» ефект підстрибування при зміні жесту, який видно у відео на **00:01**, **00:09** та **00:16**.
3. **Lip-sync (**`activeMouth`**):** Беремо індекс \\lfloor t \\times \\text{audioFps} \\rfloor із масиву `audioEnvelope`. Щоб рот не «тремтів» на кожному кадрі (chatter effect), варто брати ковзне середнє за 2–3 сусідні семпли або утримувати стан мінімум 2–3 кадри (\~50–80 мс).
4. **Процедурне кліпання (**`activeEyes`**):** Щоб не прописувати кліпання вручну, використовуємо детермінований псевдовипадковий хеш від часу (наприклад, кожні 3.5 секунди з невеликим зміщенням через `Math.sin(Math.floor(t / 3.5) * 999)` закривати очі на `0.12s`).

## 3. Секрет рендерингу «Стікер-обводки» (CSS / Canvas Trick)

Найцікавіший технічний момент у відео — те, що сам персонаж має чітку піксельну сітку, а біла обводка навколо нього **гладка і динамічно обтікає руки**, коли вони виходять за межі тулуба (особливо помітно на **00:09** у позі `shrug` та на **00:16** з піднятим кулаком).

Якщо робити це в DOM/HTML-шарі Hyperframes:

1. **Піксельна чіткість:** Усі внутрішні `<img>` шари (`base`, `eyes`, `mouth`, `pose`) складаються абсолютно (`position: absolute; inset: 0`) із властивістю:
   ```css
   image-rendering: pixelated; /* або crisp-edges */
   
   ```
2. **Групова обводка поверх композиту:** Обводка накладається **не на окремі спрайти**, а на батьківський контейнер усього аватара. Найчистіший спосіб у CSS/Canvas — використати SVG-фільтр `<feMorphology operator="dilate">` разом із `<feDropShadow>`:

```html
<svg width="0" height="0" style="position: absolute;">
  <filter id="sticker-effect" x="-20%" y="-20%" width="140%" height="140%">
    <!-- 1. Розширюємо альфа-канал усього зібраного персонажа на N пікселів -->
    <feMorphology in="SourceAlpha" result="DILATED" operator="dilate" radius="8" />
    <!-- 2. Заливаємо розширену область білим кольором -->
    <feFlood flood-color="#F8F6F0" flood-opacity="1" result="WHITE" />
    <feComposite in="WHITE" in2="DILATED" operator="in" result="OUTLINE" />
    <!-- 3. Додаємо м'яку тінь під білу обводку -->
    <feDropShadow in="OUTLINE" dx="0" dy="8" stdDeviation="10" flood-color="#000" flood-opacity="0.35" result="SHADOWED_OUTLINE" />
    <!-- 4. Накладаємо оригінального піксельного персонажа зверху -->
    <feMerge>
      <feMergeNode in="SHADOWED_OUTLINE" />
      <feMergeNode in="SourceGraphic" />
    </feMerge>
  </filter>
</svg>

```

Застосувавши `filter: url(#sticker-effect)` до контейнера аватара, ти автоматично отримуєш ідеальний білий контур і тінь, які перебудовуються в реальному часі при будь-якому русі рук без жодних артефактів на стиках шарів.

## 4. Автоматизація в пайплайні (Як не розставляти пози вручну)

Щоб цей компонент працював повністю автоматично під час генерації ролика:

- **Крок 1 (Audio Pre-pass):** Під час завантаження TTS/аудіодорожки утиліта за долі секунди проганяє `AudioBuffer` або `ffmpeg` і витягує масив гучності `audioEnvelope` (наприклад, 30 значень на секунду).
- **Крок 2 (Auto-Gesture Tagger):** Якщо у тебе вже є транскрипт із таймкодами слів (наприклад, для тих самих субтитрів зверху екрана, що й у референсі), простий правила-мапер або LLM-промпт розмічає пози:
  - Питання (`what`, `why`, `how`, `?`) \\rightarrow `shrug` (як на **00:09–00:12**).
  - Акценти / цифри / стоп-слова (`stop`, `first`, `wait`, `look`) \\rightarrow `point_up` (як на **00:01** та **00:04**).
  - Звернення (`you`, `he`, `every`) \\rightarrow `point_viewer` (як на **00:00**, **00:03**, **00:06**).
  - Фінал / кульмінація \\rightarrow `fist` (як на **00:16**).

## 5. Як генерувати самі спрайт-паки

Щоб швидко створювати нових персонажів під цей компонент, не обов'язково малювати всі шари з нуля:

1. Генеруєш **базовий піксель-арт портрет** із закритим ротом і опущеними руками (в стилі 16-bit SNES / Habbo / Stardew Valley).
2. Через **Inpainting** (або простий редактор на кшталт Aseprite) робиш 2 додаткові варіанти рота (там буквально 15–20 пікселів різниці) і 1 кадр заплющених очей.
3. Окремо домальовуєш або інпейнтиш 5 варіантів рук, які накладаються найвищим шаром поверх худі.

Як у тебе зараз у Hyperframes організована робота з аудіодорожкою — компонент має доступ до сирого аудіо/веб-аудіо контексту під час рендеру, чи краще передавати вже запечений масив амплітуд у JSON-конфізі сцени?
